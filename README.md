# 共创营销 Demo · 商家 × AI × 老客

> **商家定框架，AI 出任务，老客出真话，AI 适配全网，按真实贡献发店铺福利。**

一个跑得起来的完整闭环 Demo：本地生活商家不用自己硬写内容，而是用 AI 把老客拉进来共创 ——
老客只填几个空、传一张实拍图，AI 把这份真实素材加工成小红书 / 抖音 / 大众点评 / 朋友圈四种调性的内容，
并按**可拆解、绑定真实引流效果**的贡献值规则，自动发放店铺福利。

不是又一个 AI 文案工具。**差别在最后一步：内容是被"用起来"的，贡献是被"结算"的。**

---

## 为什么是"共创"而不是"AI 写稿"

纯靠商家用 AI 硬写，必然同质化、广告感重、平台不爱推。把老客拉进来补上的是**真实体验和实拍图**这一层，
AI 再负责加工和适配 —— 内容更能打，同时激活老客、拉来新客。

但这条路上有两个必然踩到的坑，这个 Demo 把它们的解法都落进了代码：

| 坑 | 后果 | 本项目的解法 |
| --- | --- | --- |
| 放开让老客自由创作 | 内容质量和合规会同时崩 | 老客**只做结构化填空**（一句感受 / 一张实拍图 / 一个推荐项），AI 只在商家设定的框架内加工 |
| 「交稿就给钱」 | 退化成廉价刷稿，对卖货没帮助 | 贡献值**分级绑定真实贡献**：被采用 +30、带来真实点击 +5/次（封顶 50），而不是提交即全额 |

## 闭环

```
商家                                          AI                              老客
 │                                            │                                │
 ├─ 录入店铺信息 / 卖点 / 合规禁词 ──────────► │                                │
 │                                            ├─ 生成各平台内容框架             │
 │                                            ├─ 生成轻量任务卡（只让填空）      │
 │                                            └─ 建议奖励阶梯                   │
 │                                                                             │
 ├─ 分享 H5 链接 / 门店二维码 ────────────────────────────────────────────────► │
 │                                                                             ├─ 30 秒填空 + 传实拍图
 │                                            ┌───────────────────────────────┤
 │                                            ├─ 风控校验（查重/灌水/截流/禁词） │
 │                                            ├─ 加工成 4 个平台调性的内容       │
 │◄─ 内容库（逐条可追溯素材来源）─────────────┤                                │
 │                                            └─ 结算贡献值 ──────────────────► ├─ 拿店铺福利券
 ├─ 采用内容 / 到店核销                                                          ├─ 内容被分享
 │                                                                             │
 └──────────────── 陌生访客点开分享 → 贡献值自动 +5（封顶 50）◄──────────────────┘
```

## 四个关键设计决策

这些都是实际做了之后改出来的，不是一开始就想到的：

**1. AI 层必须可降级。**
`LLM_MODE=auto`（默认）：有 key 走模型，超时 / 限流 / 欠费 / 返回结构不合法，**自动降级到内置规则引擎**，
产出结构完全一致，`aiMode` 字段如实标注走了哪条路，界面上也明说。
理由很实际：演示现场断网或 key 失效，Demo 不能开天窗。

**2. 奖励阈值不让模型决定。**
实测踩到的坑：模型不知道本系统的积分尺度，生成了 `threshold = 1/3/5` 的奖励阶梯 ——
而老客提交一次就能拿 50 分，等于**一提交就解锁全部福利，商家预算瞬间被击穿**。
修法不是调提示词了事，而是划清边界：**AI 出内容，规则定经济**。
档位名、福利内容、面额用模型写的；`threshold` 一律由 `canonicalThresholds()` 强制映射到 `[50, 120, 260]`。

**3. 严格区分「老客的第一人称体验」和「店铺的客观信息」。**
同样实测发现的：模型把商家的卖点当成了老客的体验，写进小红书正文的「真实体验」分点里 ——
老客根本没提交过那道菜。这直接打脸"不编造老客没提到的体验"这条核心主张。
修法是提示词里给死规则：第一人称体验只能来自素材；卖点只能写成客观陈述（「他们家主打 X」），
不能写成「我吃了 X，很香」，还要把商家卖点在 `mustInclude` 里明确标注"仅可作客观信息提及"。
修复后模型会写成「他们家还有凌晨到的鲜毛肚，**下次来试试**」—— 承认自己没吃过。

**4. `TrackEvent` 表是"奖励绑定引流效果"唯一真正的技术落点。**
分享链接带 `shareToken` → 陌生人打开记 `view`、点 CTA 记 `click` → 贡献值当场 +5。
并且：同访客对同内容只计一次、**自己点自己的分享不计分**、单项封顶 50。
没有这张表，"绑定真实效果"就只是一句口号。

## 技术栈

| 层 | 选型 | 说明 |
| --- | --- | --- |
| 框架 | Next.js 15（App Router）+ React 19 + TypeScript | 一个仓库一个进程，前后端与接口同构 |
| 样式 | Tailwind CSS 4 | 自定义设计令牌，**不引外部字体**（构建期不联网） |
| 数据库 | SQLite + Prisma 6 | 零外部依赖，clone 下来即可跑 |
| AI | 任何 OpenAI 兼容接口 | 默认 DeepSeek，可换通义 / 智谱 / OpenAI / 自建网关 |
| 二维码 | `qrcode`（服务端出图） | 自动探测局域网 IP，手机真能扫 |

> **关于 SQLite + JSON**：SQLite 不支持 `Json` / 数组 / enum，所有结构化字段以 `String` 存 JSON，
> 在 `lib/json.ts` 做类型化出入口。好处是换 Postgres 时字段无需改动。

## 快速开始

```bash
# 1. 安装依赖（Node.js >= 20）
#    postinstall 会自动从 .env.example 生成 .env。少了这一步，
#    后面的 db:push / db:seed 会报 P1012「Environment variable not found: DATABASE_URL」。
pnpm install

# 2. 配置 AI key（可选，有两种方式）
#    方式一（推荐，不用改文件）：启动后打开 http://localhost:3000/merchant/settings
#      在页面上粘贴 key → 点「测试连接」确认可用 → 保存，**立即生效、无需重启**
#    方式二：编辑 .env 里的 LLM_API_KEY
#    两种都不填也能跑完整闭环 —— AI 层自动降级到内置规则引擎

# 3. 建库 + 载入演示数据
pnpm db:push
pnpm db:seed

# 4. 启动
pnpm dev
```

打开 http://localhost:3000 —— 落地页有「商家工作台」和「老客 H5」两个入口。

> **演示活动的入口地址是固定的**：http://localhost:3000/c/demo-cocreate
> 种子数据用的是固定 token 而不是随机短码，所以**反复 `pnpm db:reset` 也不会让这个链接失效** ——
> 演示前重置数据是高频动作，链接不能跟着变。

### 在浏览器里配置 AI 密钥

打开 **http://localhost:3000/merchant/settings**（商家后台右上角「AI 设置」），可以：

- 粘贴任意 OpenAI 兼容接口的 key，点「**测试连接**」当场验证能不能用
- 保存后**立即生效，不需要重启服务**
- 界面只显示掩码（`sk-1ed****bada`），**从不回显完整密钥**
- 留空某项并保存 = 删掉这一项界面设置，让 `.env` 重新接管

**优先级：界面设置 > 环境变量（.env）**。所以 CI / 部署环境仍然可以只用环境变量，
而界面上填过的会覆盖它 —— "刚填了怎么不生效"不会发生。

> ⚠️ **存储说明**：密钥以**明文**保存在本地 SQLite 的 `Setting` 表里。
> 单机 Demo 可以接受；生产环境请改用密钥管理服务（KMS / Vault）或加密存储。
> 另外这个页面受 `MERCHANT_PASSWORD` 保护 —— 没设口令时它和其他商家页面一样开放，
> 那种情况下**不要在公网部署上填真 key**。界面上也如实标注了这两点，不假装它安全。

```bash
node scripts/smoke-test.mjs   # 需要先 pnpm dev
```

部署设了 `MERCHANT_PASSWORD` 时会自己登录，两种模式都能跑。

### 验证「注释承诺 == 代码行为」

```bash
pnpm verify:promises   # 不需要 dev server
```

这个脚本专门守一类最难发现的问题：**注释/文案承诺了，代码没做。**
本项目实测踩到过 4 处（`LLM_MODE=llm` 声称失败即报错、频次提示声称超出不计分、
禁词提示声称 AI 会替换、`compare-engines` 声称会报错暴露），全部改对后
用这个脚本钉住，避免退化回去。改动 AI 层或计分规则后请重跑。

### 环境变量

| 变量 | 说明 |
| --- | --- |
| `DATABASE_URL` | SQLite 路径，默认 `file:./dev.db` |
| `LLM_MODE` | `auto`（默认，失败自动降级）/ `llm`（**严格模式**：失败直接抛错，不允许静默降级）/ `rule`（强制走规则引擎） |
| `LLM_API_KEY` | 模型 key。留空则全程使用规则引擎 |
| `LLM_BASE_URL` | 默认 `https://api.deepseek.com`，任何 OpenAI 兼容接口均可 |
| `LLM_MODEL` | 默认 `deepseek-chat` |
| `MERCHANT_PASSWORD` | 商家后台口令。**留空 = 演示模式**，商家接口完全放开（界面顶部会显示「演示模式 · 未鉴权」横幅）。填上后 `/merchant/*` 与 `/api/merchant/*` 都需要先过口令页，未授权页面 307 跳转、接口 401 |

> `.env` 已在 `.gitignore` 中，**不会被提交**；仓库里只有 `.env.example`。

### 跑不起来？先看这三条

都是本项目**实际踩到过**的坑，报错信息和对应处理照抄即可：

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 页面/接口**间歇性 500**，终端里出现 `SyntaxError: Unexpected end of JSON input` 或 `Cannot find module './xxx.js'`，且日志紧挨着有一行 `○ Compiling /_error ...` | `.next` 构建缓存损坏（dev server 长时间运行、或被强杀过）。这是 Next dev 的缓存问题，**不是业务代码报错** | 停掉 dev server → 删掉 `.next` 目录 → `pnpm dev` 重启。**不要去改业务代码** |
| `P1012 Environment variable not found: DATABASE_URL` | `.env` 没生成。`postinstall` 负责从 `.env.example` 拷贝，跳过 `pnpm install` 就会缺 | 手工复制一份 `.env`（内容照抄 `.env.example`） |
| `EPERM: rename ... query_engine-windows.dll.node` | dev server 正占用着 Prisma 引擎文件，`prisma generate` 改不动它 | 先停 dev server，再跑 `pnpm db:push` / `prisma generate` |

> 排查这类问题的正确姿势是**看 dev server 自己的终端输出**。上面那条间歇性 500 的真实原因
> （缓存文件解析失败）就写在它的 stderr 里 —— 只看浏览器或只看测试脚本的报错，
> 很容易把它误判成业务 bug。

## 演示脚本（约 5 分钟）

**准备**：`pnpm db:seed && pnpm dev`，浏览器开 `/merchant`，手机连同一局域网待用。
老客入口固定为 `/c/demo-cocreate`，重置数据后依然可用。

1. **商家建活动（0:00–1:30）** —— `/merchant/campaigns/new`
   选已有店铺「椒香里·重庆老火锅」，营销目标选「团购转化」，勾选 4 个平台，点生成。
   → 强调：**AI 出的是框架和任务卡，边界是商家定的**；
   切到「任务卡与二维码」Tab，指出每个字段都写了「设计意图」，并说明为什么只让填空不让写作文。

2. **老客现场参与（1:30–3:00）** —— 手机扫二维码
   填一句感受 + 推荐项 + 场景 + 一个细节，拍一张现场图提交。
   → 强调：**免登录、30 秒、不用写一个字**。
   提交后当场看到：贡献值拆解（每一分为什么给）、四平台内容产出、解锁的福利券。

3. **引流归因当场发生（3:00–3:30）** —— 在手机结果页点开任意一条内容的分享页，
   点「我也去过这家，去贡献一条」。
   → 回到商家后台「贡献榜」，**刚才那位老客的贡献值和「带来点击」当场变了**。
   这是"奖励绑定真实引流效果"最直观的证据。
   （补充：同一访客只计一次、自己点自己的分享不计分 —— 这两条也可以当场演示。）

4. **商家侧采用与核销（3:30–4:30）**
   「内容库」Tab：切平台看同一份素材的不同调性表达；注意每条内容上方都展示**老客提交的原始素材**
   （内容可追溯）；点「采用这条内容」，贡献值 +30。
   「素材与风控」Tab：看那几条被故意埋进去的坏样本 —— 重复图、含微信联系方式、写违禁词、没传图，
   每条拦截/提醒都有**可读的理由**。
   「奖励账本」Tab：核销一张券。
   头部还有「**结束活动**」按钮 —— 点一下再看 H5，会显示"活动已结束"而不是提交表单
   （老客已拿到的券仍然保留并可核销）。

5. **收尾（4:30–5:00）** —— 两个可选的加分项：
   - 切 `LLM_MODE=rule` 重启，重跑一遍第 1 步，说明**断网 / 没 key 时 Demo 依然完整可跑**，
     界面会如实标注"规则引擎生成"。
   - 在 `.env` 里设一个 `MERCHANT_PASSWORD` 重启，展示商家口令页 ——
     同时说明默认留空是为了演示零门槛，且**没设口令时界面会明确标注「未鉴权」**，
     不让安全缺口是隐形的。

## 明确不做的部分

这是一个用来**验证玩法闭环**的 Demo。以下重模块明确后置，不假装已经做完：

- **真实多平台一键发布** —— 各平台开放接口与账号风控成本极高，不是 Demo 阶段该碰的
- **精细效果归因** —— 需要平台侧数据回传，现用分享链接的 view/click 上报模拟
- **自动结算打款** —— 涉及资金合规，且我们主张奖励只用店铺福利
- **完整风控反刷** —— 现做图片 sha256 查重 + 频次限制 + 灌水检测 + 私域截流拦截
- **账号体系** —— 老客侧改用免登录 token 链接，刻意降低参与门槛。
  商家侧提供**最简口令保护**（`MERCHANT_PASSWORD`，默认留空 = 演示模式），
  见下方环境变量说明。
- **感知哈希 / 图像相似度检索** —— 现用文件内容 sha256，**能挡住同一张图重复提交，挡不住裁剪或加水印后的二次上传**

### 已知限制（如实记录）

- 内容生成的**事实边界仍靠提示词约束**，不是硬校验。已针对"把商家卖点写成老客体验"这个具体失效模式加了铁律，
  但生产环境应该再加一层：对产出做「素材实体比对」，命中了素材里不存在的人财物就要人工复核。
- 抖音的标题与「0-3 秒钩子」内容重复，属于可接受但可优化项。
- 规则引擎产出是模板拼装，调性差异不如真模型明显 —— 它是**安全网**，不是替代品。

```bash
pnpm start         # 跑生产构建（与 build 用同一目录）
pnpm db:push       # 同步 schema 到 SQLite
pnpm db:seed       # 载入演示数据（离线、可复现、零成本，用规则引擎生成内容）
pnpm db:reset      # 重置数据库 + 重新载入
pnpm setup         # generate + push + seed 一条龙
pnpm demo:ai       # 用真实大模型重跑种子内容（演示前跑一次，见下）
pnpm demo:mine     # 重建「你自己的演示活动」（走真实大模型，可反复执行）
pnpm verify:promises          # 验证「注释承诺 == 代码行为」（12 项，不需要 dev server）
node scripts/smoke-test.mjs   # 端到端冒烟测试（45 项，需先 pnpm dev）
npx tsx scripts/compare-engines.ts   # 同一份老客素材，规则引擎 vs 大模型产出并排对比
```

> ⚠️ **`pnpm db:seed` / `db:reset` 会清空所有表** —— 包括你手工建的活动和 H5 提交记录。
> 这是种子数据的正常行为。演示前重置数据后用 `pnpm demo:mine` 把"你自己的活动"建回来。

### 为什么要 `db:seed` + `demo:ai` 两步

这两个命令服务的是**两个不同的目的**，刻意分开：

| | `pnpm db:seed` | `pnpm demo:ai` |
| --- | --- | --- |
| 用途 | 开发、测试、CI | **演示** |
| AI 层 | 内置规则引擎（模板拼装） | **真实大模型** |
| 耗时 | 几秒 | 约 1–2 分钟 |
| 成本 | 零 | 约 65 次模型调用 |
| 联网 | 不需要 | 需要 |

种子用规则引擎是为了**离线可复现**（没有 key 也能完整跑通，这正是 AI 层降级设计的价值）。
但代价是后台的「AI 生成质量」面板会显示「大模型 0% / 规则引擎 100%」——
而那恰恰是演示时最该展示的地方。所以演示前额外跑一次：

```bash
pnpm db:seed && pnpm demo:ai
```

`demo:ai` 会做三件事，**全部是"建立配对"而不是"覆盖"** —— 谁都不覆盖谁：

1. 为每份素材的每个平台**补一份规则引擎对比版**（本地生成，零 API 成本）
2. 用大模型写出**大模型版**，作为内容库展示的那一版
3. 用大模型重建 10 个活动的框架，并**按新阶梯重新结算福利**
   （档位名变了，账本必须跟着重算，否则老客会凭空多拿一份）

于是同一份素材、同一个平台会有**两版产出共存**，在「内容库」里一键切换对看。
切到规则引擎版能直接看到模板拼装的毛病 —— 标题被硬截断、分点撞车（推荐项和卖点重复成
`1️⃣` 和 `2️⃣`）、偶尔出病句。这比口头说"AI 比模板强"有说服力得多。

> **质量面板只统计"当前采用的那一版"**，对比版单独报数、不进比例。
> 把对比版也算进去的话，比例会变成假的 50/50 —— 那比不统计更误导人。

它**可反复执行**：已经有大模型版、对比版也齐了的素材会自动跳过，中断后重跑只补没跑完的。
想跳过框架重建用 `--no-blueprints`；不想要对比版用 `--no-compare`；省额度用 `--limit 20`。

> `compare-engines.ts` 是理解本项目 AI 层最直观的方式：两个引擎吃同一份输入、
> 吐同一个结构，差别只在内容质量。强制走大模型（`LLM_MODE=llm`），
> 模型有问题会直接报错而不是悄悄降级。
